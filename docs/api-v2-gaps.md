# API v0.2 설계와 현재 구현의 차이

이 문서는 `GoPick_API_설계_v0.2_수정본.docx`와 현재 저장소 구현을 비교한 결과와
추가로 확인할 사항을 정리합니다. 아직 구현되지 않았거나 합의가 필요한 내용이므로,
현재 API 사용 방법은 [API 사용 안내](api-usage.md)를 확인해주세요.

## 1. 프로필 생성 데이터

- **현재 동작:** `POST /profiles`는 희망 역할을 `roles`로 받고, `preferences`와
  `experiences`는 요청에서 처리하거나 저장하지 않습니다.
- **v0.2 기준:** 프로필 생성 예시에 `preferredRoles`, `preferences`, `experiences`가 포함됩니다.
  현재 구현에서는 이 필드들을 v0.2 형식으로 보내도 상세 조회에 반영되지 않습니다.
- **필요한 작업:** 요청 필드와 저장 로직을 v0.2에 맞추고, 생성한 데이터를 상세 조회로
  확인합니다. 경험 등 문서에 구체적인 구조가 없는 필드는 프론트엔드와 합의가 필요합니다.

## 2. 프로필 생성 오류 처리

- **현재 동작:** 이미 프로필이 있는 계정에는 `409 DUPLICATE_PROFILE`을 반환합니다.
  `parts`, `interests`, `roles`, `technologies`에 명시적으로 `null`을 보내면
  저장 과정에서 서버 오류가 발생할 수 있습니다.
- **v0.2 기준 또는 부족한 점:** 중복 프로필 오류 코드는 `PROFILE_ALREADY_EXISTS`입니다.
  잘못된 배열 입력은 서버 오류 대신 입력 오류로 처리할 필요가 있습니다.
- **필요한 작업:** 중복 오류 코드를 설계에 맞추고, 배열 입력의 허용 범위와
  유효성 검사를 정한 뒤 정상 및 오류 사례를 테스트합니다.

## 3. 로그아웃 인증

- **현재 동작:** `POST /auth/logout`은 세션이 없어도 `204 No Content`를 반환합니다.
- **v0.2 기준:** 비로그인 요청은 `401 UNAUTHENTICATED`를 반환해야 합니다.
- **필요한 작업:** 인증 상태 확인과 비로그인·로그인 로그아웃 테스트를 추가합니다.

## 4. 생성부터 상세 조회까지의 검증

- **현재 동작:** 상세 조회 통합 테스트는 연관 데이터를 DB에 직접 준비해 조회 결과를 검증합니다.
  테스트 DB는 H2의 MySQL 호환 모드입니다.
- **부족한 점:** 실제 `POST /profiles`로 저장한 데이터가 `GET /profiles/{profileId}`에
  그대로 나타나는 흐름은 검증하지 않았습니다. 실제 MySQL 스키마와 쿼리, 브라우저의
  세션 쿠키 및 CORS 연동도 현재 테스트만으로 확인할 수 없습니다.
- **필요한 작업:** 프로필 생성 API를 보완한 뒤 생성 → 상세 조회 통합 테스트를 추가하고,
  실제 MySQL 및 프론트엔드 연동 환경에서도 확인합니다.

## 5. 프로필 상세 조회 응답 합의

- **현재 동작:** 상세 조회 응답은 현재 데이터 모델과 v0.2 생성 예시를 바탕으로 구성했습니다.
  현재 응답 예시는 [프로필 상세 조회 API](profile-detail-api.md)에서 확인할 수 있습니다.
- **v0.2 기준 또는 부족한 점:** 상세 조회 성공 응답의 전체 스키마는 v0.2에 명시되어 있지 않습니다.
  따라서 현재 응답을 확정된 v0.2 스키마로 볼 수 없습니다.
- **필요한 작업:** 프론트엔드와 응답 필드 및 경험·속성의 구조를 합의하고 문서와 구현에 반영합니다.
