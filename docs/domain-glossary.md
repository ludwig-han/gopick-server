# GoPick 도메인 용어 및 상태 정의 v0.1

## 1. 문서 목적

GoPick의 API, ERD, 백엔드 코드, 프론트엔드 화면에서 사용하는 핵심 도메인 용어와 상태를 동일한 의미로 사용하기 위한 기준 문서입니다.

구현 과정에서 용어의 의미가 변경되거나 새로운 규칙이 확정되는 경우 이 문서를 함께 갱신합니다.

---

## 2. Account

서비스에 로그인하기 위한 **계정 정보**입니다.

주요 정보:
- 이메일
- 비밀번호
- 생성 시각

Account는 사용자를 서비스 안에서 표현하는 Profile과 구분합니다.

**Account = 로그인·인증을 위한 계정**  
**Profile = GoPick에서 다른 사용자에게 보여지는 사용자 정보**

하나의 Account는 최대 하나의 Profile을 가집니다.

---

## 3. Profile

GoPick에서 팀원을 탐색하거나 추천할 때 사용하는 **사용자의 서비스 프로필**입니다.

다음과 같은 정보를 포함합니다.

- 이름
- 전공
- 소속 부문
- 관심 분야
- 기술 스택 및 숙련도
- 희망 역할
- 협업 성향
- 프로젝트 경험
- 자기소개 등

### 공개 상태

Profile은 공개 또는 비공개 상태를 가질 수 있습니다.

**공개 Profile**
- 프로필 검색 가능
- 팀원 추천 대상이 될 수 있음
- 다른 사용자가 상세 정보를 조회할 수 있음

**비공개 Profile**
- 검색 및 추천 대상에서 제외
- 본인 외 사용자는 상세 정보를 조회할 수 없음
- 기존에 북마크한 사용자의 목록에서는 “비공개 프로필” 상태만 표시하며 상세 정보는 노출하지 않음

---

## 4. Project

사용자들이 팀을 구성하고 진행하는 **프로젝트 자체**를 의미합니다.

Project는 다음 세 가지 상태 개념을 구분해서 관리합니다.

### 4.1 Project Status

프로젝트의 **전체 생명주기 상태**입니다.

#### PREPARING

프로젝트가 아직 공식적으로 시작되지 않은 상태입니다.

- 팀원을 공개 모집할 수 있음
- APPLY를 받을 수 있음
- 팀장은 OFFER를 보낼 수 있음
- 팀장이 프로젝트 시작을 실행하면 IN_PROGRESS로 전환

#### IN_PROGRESS

팀장이 프로젝트 시작을 실행한 이후의 상태입니다.

- 프로젝트가 실제로 진행 중임
- 공개 모집은 할 수 없음
- `recruiting = false`
- 팀장은 특정 사용자에게 OFFER를 보낼 수 있음
- 팀장은 다른 팀원에게 팀장 직위를 위임할 수 있음

#### COMPLETED

팀장이 프로젝트 완료를 명시적으로 실행한 상태입니다.

- 프로젝트의 최종 상태
- 다시 IN_PROGRESS로 되돌리지 않음
- 화면에서는 “완료·아카이브” 영역에 표시

프로젝트의 마지막 진행 단계를 완료했다고 해서 자동으로 COMPLETED가 되지는 않습니다.  
프로젝트 완료는 팀장이 별도로 실행합니다.

---

## 5. Recruiting

`recruiting`은 프로젝트가 **공개적으로 팀원을 모집하고 있는지**를 나타냅니다.

프로젝트 진행 여부와 같은 의미가 아닙니다.

### recruiting = true

- 공개 모집 중
- 프로젝트 탐색의 “모집 중” 영역에 표시
- 사용자가 APPLY를 보낼 수 있음

### recruiting = false

- 공개 모집 종료
- 일반 사용자는 APPLY를 보낼 수 없음

단, 공개 모집 여부와 관계없이 팀장은 특정 사용자에게 OFFER를 보낼 수 있습니다.

### Project Status와의 관계

`recruiting = true`는 PREPARING 상태에서만 가능합니다.

프로젝트를 시작하면:

`PREPARING → IN_PROGRESS`

로 상태가 변경되며 동시에:

`recruiting = false`

로 변경됩니다.

따라서 **IN_PROGRESS 상태에서 공개 모집을 진행하지 않습니다.**

---

## 6. Stage

Project의 `stage`는 프로젝트가 현재 **실제 작업 과정 중 어느 단계에 있는지** 나타냅니다.

예:

`기획 → 설계 → 구현 → 테스트 → 배포`

Project Status가 프로젝트 전체 생명주기를 나타낸다면, Stage는 IN_PROGRESS 프로젝트 내부의 구체적인 진행 상황을 표현합니다.

프로젝트 팀장과 팀원 모두 Stage를 변경할 수 있습니다.

Stage의 마지막 단계에 도달하더라도 프로젝트가 자동으로 COMPLETED 상태가 되지는 않습니다.

---

## 7. ProjectMember

특정 Project에 실제로 참여하고 있는 **프로젝트 구성원**을 의미합니다.

ProjectMember에는 프로젝트에서 맡은 역할과 프로젝트 내 권한을 구분해서 관리합니다.

예:

- Backend + LEADER
- Frontend + MEMBER
- Design + MEMBER

즉, Backend / Frontend 등의 역할과 LEADER / MEMBER는 서로 다른 개념입니다.

---

## 8. LEADER

프로젝트의 **팀장 권한을 가진 ProjectMember**입니다.

한 프로젝트에는 한 명의 LEADER가 존재합니다.

LEADER는 일반 MEMBER가 가진 권한에 추가하여 다음 권한을 가집니다.

- 프로젝트 기본 정보 수정
- 모집 조건 수정
- 공개 모집 여부 변경
- 프로젝트 시작
- 프로젝트 완료
- APPLY 승인 및 거절
- 특정 사용자에게 OFFER 전송
- 다른 ProjectMember에게 팀장 직위 위임
- 프로젝트 삭제

프로젝트 진행 중 LEADER는 바로 프로젝트에서 하차할 수 없습니다.

먼저 다른 MEMBER에게 LEADER 직위를 위임한 후 하차해야 합니다.

---

## 9. MEMBER

프로젝트에 참여하고 있지만 팀장 권한은 가지지 않는 **일반 ProjectMember**입니다.

MEMBER는 다음 작업을 수행할 수 있습니다.

- 프로젝트 진행 단계(Stage) 변경
- 본인 프로젝트 하차

프로젝트 제목, 설명, 모집 조건 등 프로젝트의 일반 정보는 수정할 수 없습니다.

APPLY 승인·거절이나 OFFER 전송 역시 LEADER만 수행할 수 있습니다.

---

## 10. 프로젝트 시작

프로젝트 시작은 단순한 Stage 변경이 아니라 프로젝트 생명주기를 변경하는 행동입니다.

LEADER만 실행할 수 있습니다.

프로젝트 시작 시:

`PREPARING → IN_PROGRESS`

로 변경되며 공개 모집도 종료됩니다.

`recruiting = false`

프로젝트 시작 이후에도 LEADER는 특정 사용자에게 직접 OFFER를 보낼 수 있습니다.

---

## 11. 프로젝트 완료

LEADER가 프로젝트가 종료되었다고 명시적으로 결정하는 행동입니다.

`IN_PROGRESS → COMPLETED`

로 변경됩니다.

COMPLETED는 프로젝트의 최종 상태이며 다시 IN_PROGRESS로 되돌리지 않습니다.

---

## 12. 프로젝트 하차

ProjectMember가 프로젝트 참여를 중단하는 행동입니다.

상태와 권한에 따라 처리 방식이 다릅니다.

### PREPARING + MEMBER

ProjectMember만 제거합니다.

프로젝트는 그대로 유지됩니다.

### PREPARING + LEADER

아직 프로젝트가 시작되지 않은 상태에서 팀장이 하차하는 경우 프로젝트 자체를 삭제합니다.

이 경우 프로젝트 데이터는 **hard delete** 합니다.

### IN_PROGRESS + MEMBER

해당 ProjectMember가 프로젝트에서 정상적으로 하차합니다.

### IN_PROGRESS + LEADER

바로 하차할 수 없습니다.

팀장 직위를 다른 MEMBER에게 위임한 뒤 하차해야 합니다.

위임하지 않은 상태에서 하차를 요청하면 오류를 반환합니다.

---

## 13. 프로젝트 삭제

LEADER가 프로젝트 자체를 명시적으로 삭제하는 행동입니다.

일반적인 프로젝트 삭제는 **soft delete**로 처리합니다.

즉 데이터 자체를 즉시 제거하기보다 삭제 상태로 전환하여 일반 조회에서 제외합니다.

단, PREPARING 상태에서 LEADER가 하차하여 프로젝트 자체가 사라지는 경우에는 별도로 **hard delete** 합니다.

---

## 14. APPLY

사용자가 공개 모집 중인 프로젝트에 **직접 참여를 신청하는 요청**입니다.

조건:
- `PREPARING`
- `recruiting = true`
- 이미 프로젝트 구성원이 아니어야 함

APPLY에 대한 승인 또는 거절은 LEADER만 할 수 있습니다.

---

## 15. OFFER

LEADER가 특정 사용자에게 **프로젝트 참여를 제안하는 요청**입니다.

OFFER는 LEADER만 보낼 수 있습니다.

공개 모집 여부와는 별개의 기능입니다.

따라서 `recruiting = false`인 프로젝트도 LEADER가 특정 사용자에게 OFFER를 보낼 수 있습니다.

---

## 16. ParticipationRequest

APPLY와 OFFER를 하나의 도메인으로 관리하는 참여 요청입니다.

### Type

- `APPLY`: 사용자가 프로젝트에 지원
- `OFFER`: 프로젝트 팀장이 사용자에게 참여 제안

### Status

- `PENDING`: 응답 대기
- `ACCEPTED`: 수락
- `REJECTED`: 거절
- `CANCELED`: 요청을 보낸 쪽에서 취소

참여 요청이 ACCEPTED되면 실제 ProjectMember가 생성됩니다.

---

## 17. 추천 / 매칭

프로젝트에 적합한 Profile을 탐색하거나 추천할 때 다음 요소를 우선적으로 고려합니다.

우선순위:

1. 기술 스택
2. 협업 성향
3. 프로젝트 경험
4. 학과 및 소속 부문

프로젝트 경험은 구현 난이도와 실제 데이터 구조를 검토한 뒤 추천 점수 반영 방식과 비중을 확정합니다.

### 기술 조건

필수 기술이 여러 개인 경우 모든 기술의 최소 숙련도 조건을 충족해야 합니다.

즉 필수 기술 조건은 AND 방식으로 판단합니다.

우대 기술은 조건을 충족하지 않더라도 추천 대상에서 제외하지 않고 추천 순위 계산에 반영합니다.

## 18. 주요 권한 요약

| 기능 | LEADER | MEMBER |
|---|---|---|
| 프로젝트 기본 정보 수정 | 가능 | 불가 |
| 모집 조건 수정 | 가능 | 불가 |
| 공개 모집 설정 변경 | 가능 | 불가 |
| 프로젝트 시작 | 가능 | 불가 |
| 프로젝트 완료 | 가능 | 불가 |
| 진행 단계(Stage) 변경 | 가능 | 가능 |
| APPLY 승인·거절 | 가능 | 불가 |
| OFFER 전송 | 가능 | 불가 |
| 팀장 직위 위임 | 가능 | 불가 |
| 본인 프로젝트 하차 | 조건부 가능 | 가능 |
| 프로젝트 삭제 | 가능 | 불가 |

※ IN_PROGRESS 상태의 LEADER는 다른 MEMBER에게 팀장 직위를 위임하기 전에는 하차할 수 없습니다.

---

## 19. 아직 확정하지 않은 사항

다음 내용은 추가 논의 후 확정합니다.

- LEADER가 MEMBER를 강제로 프로젝트에서 제외할 수 있는지
- 프로젝트 경험을 추천 점수에 어느 정도 반영할지
- 추천 점수를 사용자 화면에 직접 노출할지
- 알림(Notification)의 상세 구조 및 API

알림은 별도 도메인 설계 전까지 다음과 같은 주요 이벤트에서 필요할 수 있음을 인지하고 구현 시 고려합니다.

- APPLY / OFFER 도착
- APPLY / OFFER 승인·거절
- 팀장 직위 위임
- 팀원 하차
- 프로젝트 상태 변경
- 프로젝트 삭제
